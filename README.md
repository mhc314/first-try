# How to photograph

一款正在构思中的像素风摄影解谜游戏。玩家扮演摄影师，接受拍摄委托，通过观察场景、调整相机参数并提交照片获得报酬。

游戏希望让玩家通过拍摄和比较照片，理解光圈、快门速度、ISO 与对焦对成像的影响。早期委托以自然物品为主，后续计划加入原创的超自然拍摄对象；相机和器材升级是未来可能加入的功能。

## 下载试玩版

在 [GitHub Releases](https://github.com/mhc314/first-try/releases) 下载最新的 Windows 64 位试玩压缩包，解压后双击 `How-to-photograph.exe` 即可游玩，无需安装 Godot。请将游戏放在有写入权限的文件夹中。版本变化见 [更新日志](CHANGELOG.md)。

## 首个可玩版本

- 摄影棚教程：体验对焦、景深、运动模糊、亮度和噪点。
- 拍照及照片结果预览。
- 根据照片是否满足要求，给出可理解的反馈。
- 一项综合拍摄挑战；随后尝试加入一份自然场景委托。

## 本地试玩：2D 自由取景原型

这是使用 Godot 4.6.1 制作的本地原型。Windows 下双击 `start_game.bat` 即可启动。启动脚本会寻找项目文件夹内的 `tools/godot/Godot_v4.6.1-stable_win64.exe`；本地引擎放在 `tools/` 中，不纳入 Git 版本管理。

1. 在主标题选择“开始游戏”进入教学关摄影棚；之后可使用“继续游戏”回到最近的关卡和任务，或从“选择关卡”进入已解锁的关卡。现实场景铺满游戏窗口，点击左上角“任务”查看任务详情。
2. 在现实场景的目标位置点击鼠标右键，再点击鼠标附近出现的“拍摄此处”，打开取景器。按住取景器的标题栏拖动可以移动整个窗口；按住取景画面拖动则是微调构图，也可以关闭相机后重新选点。靠近场景边缘时，相机会自动限制取景范围，避免黑边。
3. 在取景器中调整光圈、快门速度、ISO、对焦位置和镜头；这些参数只影响取景器和照片，不会改变现实场景。对焦滑块从前景 0 到背景 2，可以在中间连续调整。先选择镜头组，再用焦距滑块调整视角。点击“拍照并检查任务”后会弹出照片、相机参数和具体反馈；拖动结果窗口的标题栏可以移动窗口，取景器与结果窗口都可单独关闭。在结果窗口点击“保存照片”，才会将当前照片保存为 PNG。
4. 教学关包含摄影棚的对焦、景深、运动和暗光练习，以及窗边花园的拍花练习。摄影棚和花园属于同一关，可以随时用屏幕边缘的方向箭头切换；靠近花园后还可以查看窗边近景。
5. 主标题和游戏中的 `Esc` 暂停菜单均可打开游戏手册，查看操作、光圈、快门、ISO、对焦、焦距等说明。暂停菜单还可以继续游戏、查看已保存的照片或返回标题。相册中使用“上一张”和“下一张”浏览程序旁 `Photos` 文件夹里的 PNG；在相册或手册中按 `Esc` 可以返回上一层。

试玩版在游戏 `.exe` 所在文件夹的 `GameProgress/progress.json` 中自动保存已完成任务以及当前关卡和任务，重新打开游戏后仍可继续。重玩已解锁的关卡不会清除其他关卡的解锁状态。旧版摄影棚和花园的进度可读取并转换到合并后的教学关；原文件在读取时不会立即覆盖。程序会先写入临时文件再替换进度文件；如果进度无法读取，不会自动覆盖原文件。

照片保存在游戏 `.exe` 所在文件夹的 `Photos` 子文件夹里，第一次点击保存时才创建。照片为 512×288 PNG，可用系统图片查看器打开；同一秒内多次保存会使用不同文件名。请将游戏放在有写入权限的位置。通过 `start_game.bat` 从项目运行时，`GameProgress` 和 `Photos` 均位于项目文件夹内。如果将可执行文件移动到其他文件夹，请同时复制 `GameProgress` 和希望保留的 `Photos` 文件夹。

当前场景使用 512×288 的像素画布；摄影棚按室内空间重新安排了拍摄桌、背景纸、灯具、柜子和拍摄物的比例。美术仍是可继续完善的原型。右键选点后的按钮会显示在点击位置附近，并在窗口边缘自动调整位置。

照片的亮度、景深、运动模糊和噪点采用便于观察的简化模拟，不是精确的光学成像。对焦滑块是场景深度的相对位置，并非以米为单位的实际距离；画面仍按前、中、背景层模拟清晰度。拍摄判定会检查指定目标是否大部分进入画面及参数是否满足要求；目前没有独立的遮挡判定。镜头通过裁切和缩放 2D 画面模拟视角变化，不模拟真实的空间透视；取景范围会限制在场景内部，长焦尤其是 1000mm 时由于原始画面分辨率有限会明显像素化。镜头组是游戏中的范围划分，并不代表具体真实镜头规格。报酬和升级尚未开发。

## 未来设计方向

游戏采用 2D 平面场景与像素风。以下方向会随着试玩反馈继续调整。

### 探索与自由取景

- 玩家扮演摄影师，通过观察和探索场景，自行决定拍摄对象与构图；取景器显示玩家选择的区域。
- 已支持在现实场景中右键选点，由取景器以选点为中心显示画面；也可以在开启的取景器内按住左键拖动画面调整中心。当前镜头在 2D 场景中通过裁切模拟取景，画面不包含 3D 视差。
- 场景切换参考《绣湖》系列的点击式探索：在画面边缘显示可用的方向箭头，点击后查看其他方向，或移动到相邻的预设位置。箭头具体代表转身还是移动，由场景和界面设计明确区分。
- 游戏继续采用像素风；后续拍摄内容可从自然物品逐渐扩展到原创的超自然对象。

### 镜头、委托与拍摄判定

- 已提供 25–70mm、70–200mm 和 200–1000mm 三组模拟变焦镜头，可在组内按 1mm 调节；各关卡可以配置可用镜头组，目前教学关提供全部三组。焦距越长取景范围越窄；当前视角按 25mm 对应完整场景作简化裁切，不能视作真实传感器规格下的精确视角。
- 玩家接受拍摄委托并通过完成任务获得报酬；报酬可用于未来可能加入的相机或器材升级。
- 拍摄判定已初步结合目标在画面中的范围及摄影参数；后续可以探索遮挡、画面占比等更丰富的条件。

### 未来的超自然摄影与调查

以下内容仍是构思，尚未加入游戏。设计方向是让特殊相机接收、记录和呈现异常信息，并尽量与真实摄影参数的作用保持联系；超自然效果需要与普通摄影知识明确区分。

**负快门：调查过去。** 玩家可以设定精确的过去时间，拍摄玩家到达场景之前发生的事，用照片调查和还原事件。任务今后可以直接提示需要调查的时间，减少反复猜测；玩家仍需观察场景并选择合适的取景位置和构图。例如，任务提示调查昨晚 22:00 的书房，玩家对准相关区域拍摄，从过去的画面中寻找线索。这里的“负快门”是游戏中的虚构能力，不代表现实相机可以使用负的曝光时间。

**特殊 ISO：发现隐藏信息。** 可考虑让特殊感光能力显现肉眼看不到的信息，并结合画面亮度与噪点形成取舍；具体的显现规则和任务形式仍待设计。普通 ISO 的教学效果应与超自然功能区分。

**照片作为调查线索。** 可考虑在关卡内查看和比较不同时间、位置或参数拍摄的照片，通过照片中的变化推理事件，或找到任务需要的信息。现有的玩家自主保存 PNG 功能与未来关卡内的线索系统是两个不同功能，后者尚未实现。

待讨论的细节包括：如何让玩家方便地输入精确时间，是否同时显示目标时刻与相对当前游戏时间的负值、是否提供设置到任务时间的快捷选项，以及照片是否在关卡内标注所记录的时间。也可以探索将负快门与特殊 ISO 配合使用，但具体规则尚未确定。

### 场景实现方案

已确定使用 **2D 像素场景**。当前原型提供摄影棚、窗边花园和窗边近景，使用方向箭头在预设画面之间切换；画面切换时不是连续的自由行走。接下来可以根据测试反馈完善场景美术、构图体验和委托内容。

关卡配置保存在 `scripts/main.gd` 的 `LEVELS` 中，包含任务范围、初始场景、允许的场景与镜头组；选关菜单和按顺序解锁逻辑根据配置生成。后续新增关卡仍需添加相应任务、场景素材、场景连接及拍摄判定，而非仅填写配置。手册条目集中在同文件的 `MANUAL_TOPICS` 中。

## 开发环境

项目推荐使用 Godot 4.6.1 标准版。将 Windows 官方版本解压到 `tools/godot/`，并在该目录放置空文件 `_sc_`，可启用 Godot 的便携模式。`.godot/` 是引擎自动生成的项目缓存，不提交到 Git。

场景原画位于 `assets/scenes/`；若需要重新生成这两张原画，可在项目文件夹中使用已安装 Pillow 的 Python 运行 `python scripts/generate_scene_art.py`。游戏运行和试玩不需要安装 Python。

界面字体使用 [Fusion Pixel Font](https://github.com/TakWolf/fusion-pixel-font) 12px 简体中文比例版，遵循 SIL Open Font License 1.1；字体与其附带授权文件位于 `assets/fonts/`。
